# 与正式远程试点的差距清单（GAP）

本原型为**脱敏可点击演示**，刻意不做生产接入。以下为进入正式远程试点前需补齐的典型差距，供诊断会对照。

---

## 1. 数据

| 差距 | 现状（演示） | 试点需达到 |
|------|--------------|------------|
| 案件与客户主数据 | 静态假数据（姓名脱敏） | 只读对接进件/信贷中台或脱敏样本仓 |
| 材料影像与 OCR | 文案模拟结果 | 对接影像平台与既有 OCR/活体结果 |
| 征信与外部数据 | 仅展示「已授权」状态 | 在授权与最小必要原则下对接行内征信视图 |
| 特征与标签 | 无特征存储 | 明确特征字典、血缘与刷新频率 |

---

## 2. 合规与隐私

| 差距 | 现状（演示） | 试点需达到 |
|------|--------------|------------|
| 个人信息保护 | 界面层脱敏 | 分级分类、脱敏策略、访问控制与留痕 |
| 授权与用途限制 | 示意勾选 | 授权链路与用途绑定可审计 |
| 模型输出对外话术 | 模拟拒绝话术 | 合规审定话术库与禁语规则 |
| 跨境/外包 | 未涉及 | 按行方数据驻留与供应商要求评估 |

---

## 3. 系统集成

| 差距 | 现状（演示） | 试点需达到 |
|------|--------------|------------|
| 后端与 API | 无后端、无登录 | 统一身份、网关、只读/写回接口契约 |
| 工作流引擎 | 前端页跳转 | 与现有预审/补件/放行流程状态机对齐 |
| 写回核心 | 无 | 明确哪些字段可写回、谁审批、如何回滚 |
| 旁路 vs 嵌入 | 独立静态站 | 试点一期建议旁路辅屏，降低切换成本 |

---

## 4. 审计与可追溯

| 差距 | 现状（演示） | 试点需达到 |
|------|--------------|------------|
| 审计存储 | 浏览器会话内追加 | 不可篡改或行内标准审计库 |
| 模型版本与提示 | 未展示版本号 | 模型/规则/提示版本与案件绑定 |
| 人机差异分析 | 看板为模拟数 | 真实决策对比与抽检机制 |
| 监管报送口径 | 未覆盖 | 与内审/合规确认留存字段 |

---

## 5. 模型治理

| 差距 | 现状（演示） | 试点需达到 |
|------|--------------|------------|
| 模型选型与部署 | 静态文案冒充「AI 输出」 | 行内私有化或批准的云上方案 |
| 评测与漂移 | 无 | 离线评测集、在线监控与回退策略 |
| 幻觉与越权控制 | 靠文案约束 | 输出 schema、规则硬约束、拒答策略 |
| 人审覆盖策略 | 全量可点 | 按风险分层抽检/强制人审规则 |

---

## 6. 组织与运营

| 差距 | 现状（演示） | 试点需达到 |
|------|--------------|------------|
| 岗位职责 | 演示「预审岗·周*」 | 明确 AI 建议权责、改判 KPI |
| 培训与变更管理 | 无 | 操作手册、话术、例外升级路径 |
| 成功指标 | 模拟 KPI | 与业务共同定义试点 OKR 与退出条件 |

---

## 建议的远程试点切入顺序（参考）

1. **诊断**：对照本 GAP 做现状访谈与系统清单（60–90 分钟起）。  
2. **旁路辅屏**：历史/脱敏案件回放 + 审计落库，不写核心。  
3. **规则硬约束 + 人审闭环**：建议可驳、理由必填。  
4. **度量与治理**：采纳率、一致率、漂移告警进例会。  
5. **审慎写回**：仅开放经批准的字段与状态。
